# Coverage and correctness survey, 2026-10-18

ROM CRC32: `777AAC2F`. SHA-256: `66871d66be19ad2c34c927d6b14cd8eb6fc3181965b6e517cb361f7316009cfb`.

Framework: snesrecomp `48982940` (PRs #183 and #184), with recursively updated main/master dependencies. Generation policy lives in `recomp/generate.toml`; `tools/regen.sh` delegates to the framework. The recipe applies to developer regeneration and the launcher SDK. Generated C is never edited by hand or committed.

The USA survey uses the original entrance and room-transition modules with full equipment and health cheats. Fourteen dungeon entrances and thirteen boss rooms were sampled. Boss-room coordinates come from the original bank-$09 sprite placement directory, rather than assuming all rooms use the same 256-pixel quadrant. The room survey positions Link and both background scrolls in the boss's quadrant before sampling attacks and movement.

Adaptive widescreen was exercised at 1280x720, producing 398-pixel source captures. These runs cover room entry, active bosses and camera transitions; they do not certify every boss death or the ending. No speculative profile is promoted on the strength of a forced room alone.

The generation recipe retains tools/apply_widescreen_overrides.py. A launcher rebuild must run it just as a developer regeneration does.

Reference walkthrough: https://www.zeldadungeon.net/a-link-to-the-past-walkthrough/

Automated runs use a dummy output audio device while preserving audio emulation. Release defaults retain normal audio. Private ROMs, full memory captures, journals, and trial profiles remain outside the repository. A successful build or version string alone is not evidence of cross-build netplay compatibility.

Setup-pack generation also requires the native analyzer. The updated shared packager includes it and smoke-tests the staged SDK, so the bundled Python/C++ tools can generate without a Rust installation.
